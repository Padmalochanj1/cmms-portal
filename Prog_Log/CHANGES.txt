Version of 18.11.2026 (2) - Deferred orders rescheduled, Create order tab, Attention creates an order
(Includes the earlier changes: Management access to Admin and the Compliance tab.)

Files to replace:
  js/app.js          All screens.
  sw.js              New cache name so phones and browsers load the new app.js.
  server/worker.js   PASTE THIS INTO CLOUDFLARE (Workers > your worker > Edit code > Deploy). Version 2.8.

1. Deferring an order now needs a NEW DATE ("Defer to" column in Order closing and Closure report).
   The deferred order stays on its own date as DEFERRED. A new order (same number + -R1, -R2 ...) appears on the
   new date, with the same checklist rules as the original. It can be deferred again.
2. New tab "Create order" for every role: an additional maintenance order for any equipment and due date,
   without a checklist. It is closed directly in Order closing on its due date.
3. When a checklist is closed with Attention items, the portal now also creates a corrective order
   (number ACT-<order number>) due on the closing date, without a checklist, to be closed in Order closing.
   Orders closed with Attention BEFORE this update do not get one.

All three kinds are stored in the data repo in extras/YYYY-MM.json (created automatically).
They also appear on the Dashboard, Tomorrow's orders and Closure report, marked Rescheduled, Additional or
Attention action. In Compliance they are listed in a separate table and are NOT part of the percentage.
The deferred original still counts as not complied.

Update (4): User profiles (E&I sections only)
  Files: index.html, css/landing.css, js/landing.js, js/app.js, sw.js, server/worker.js (version 2.9, deploy in Cloudflare).
  - Click the user name on the index page to open My profile: Name, Emp. Code, User Type, Department, Function,

Update (5): MTTR / MTBF
  Files: index.html, js/app.js, sw.js, server/worker.js (version 3.0, deploy in Cloudflare).
  - New tab "MTTR / MTBF" (all roles, view only) and a tile on the index page. Monthly and Yearly (Jan to Dec) views.
  - Failures come from: Breakdown notifications (default, repair time = breakdown hours and minutes),
    and optionally Attention-action orders and Additional orders (repair time = closing End time - Start time).
  - MTTR = total repair time / failures. MTBF = (operating time - repair time) / failures.
    Operating time = "Operating hours per day" (default 24) x days of the period up to today, for each equipment that failed.
  - Shown overall, by area and by equipment, with availability. Equipment with no failure are not listed.

Update (7): Interruption notification type, and order types
  Files: js/app.js, css/style.css, sw.js, server/worker.js (version 3.1, deploy in Cloudflare).
  - New notification type "Interruption" (in the Log a notification list and the Type filter). It needs title and
    description only. It is NOT counted as a failure in MTTR / MTBF.
  - Create order now needs a Type of order: PM - Preventive Maintenance, CM - Corrective Maintenance,
    IM - Inspection / Lubrication / Compliance, OM - Overhauling / Refurbishment.
    The type starts the order number, e.g. CM-0001-261119-01, and is shown in Order closing, Closure report,
    Tomorrow's orders and the Create order list.
  - Corrective orders created from Attention items are type CM (number still ACT-...).
  - MTTR / MTBF: the order source "Additional orders" is now "Corrective (CM) orders": only Additional orders of
    type CM are counted. Additional orders created before this update have no type and are not counted.

Update (9): Area-wise levelled workload, one rule for every plant
  Files: js/logic.js, js/app.js, sw.js, data-repo/rmhs-ei/master.json (no Worker change).
  - From the plant's effective date (settings.balanceFrom) the areas are taken in the order of the numbers in
    Admin > Maintenance scheduling > "Assigned day for each location" (1 to 7), starting with the weekday of the
    effective date. Each area stays together on a day; when a day is full the rest of the area moves on to the next
    day, so all 7 days carry about the same number of orders (daily inspections are not part of the sequence).
  - Every equipment keeps its weekday in the new "Day" column (Admin > Equipment details; "By area" = the weekday of
    its area). New equipment follows its area. Inside its weekday it is due every 1, 2, 4, 13, 26 or 52 whole weeks
    (Weekly, Fortnightly, Monthly, Quarterly, Half-yearly, Yearly), in a week spread evenly over the cycle.
  - Level the daily workload: pick the effective date, Preview (before/after numbers, areas per day, 28-day charts),
    then Apply and save. Before the date, or while empty, the old location-day rule applies.
  - Tested: RMHS 15-21 orders a day with at most 2 areas on any day; Coal Washery 17-26 and Coke Oven 24-32 a day
    (a few days carry 3 areas where small areas cannot fill a day; change the area numbers and Preview again).
